01 — Narrative Screens

Act 1: Baudrillard's 4 Immersive Screens

Four new narrative screens immerse the viewer in Baudrillard's orders of simulacra before any data is shown. Each screen follows the format of the existing narrative frames — full-bleed background media, sparse poetic copy, keyboard navigation. The existing mp4 video backgrounds are replaced with Giphy GIFs.

Baudrillard's 4 orders provide the conceptual scaffold. Each screen should feel like it's descending — lighter at the top, darker and more abstract by Order IV. The copy is short and surgical. The GIF carries the emotional weight.

02 — Boot Sequence

Act 2: Phase Boot Sequence

After the 4 Baudrillard screens, a terminal-style loading sequence runs before the strata visualisation fades in. It functions as a data-driven recap of the archive's 55 keywords, introduces the codification score as a concept, and creates a brief moment of anticipation before the interactive view.

Behaviour

  • Full-screen dark terminal. Background: #000000. Monospaced font (Space Mono).
  • Keywords appear one by one per phase with a typed-in effect (~30ms per character or word-by-word reveal).
  • Each phase has a header line that "loads" first before its keywords appear.
  • Score value counts up numerically from 0 to final value as each keyword appears.
  • Total duration: approximately 6–8 seconds. Should feel quick and procedural, not slow.
  • Ends with a "ARCHIVE READY" line, a 0.8s pause, then cross-dissolve into the strata visualisation.
  • User can press any key or click to skip the sequence entirely.

Design Notes

  • Show the first 3 keywords of Phases 01 and 02 explicitly (highest narrative impact). Show the rest as a count summary [+N terms] to keep pacing tight.
  • The score column right-aligns with dot leaders. Score counts up from 0 to final in ~400ms using requestAnimationFrame.
  • Cursor blink ▓ at the end before transition.
  • SKIP button: top-right, fades in after 1s. PRESS ANY KEY TO SKIP →
03 — Main Visualisation

Act 3: Baudrillard Strata View

The existing Districts screen (Frame 5) is replaced with a new full-screen strata visualisation. The geological metaphor maps Baudrillard's 4 orders of simulacra as sediment layers, with 55 keywords as floating bubbles within their respective stratum.

A D3.js force-simulation prototype of this view is available for reference — see baudrillard_strata.html. The implementation notes below are additive to that prototype.

3.1 — Filter Chip Component

A row of filter chips appears at the top of the visualisation (or in a fixed top bar that appears on hover/scroll). Clicking a chip highlights matching bubbles and dims others. Multiple chips can be active simultaneously.

Chip Group Options Behaviour
Phase Before the Fall · The Cage Opens · Simulation Deepens · New Normal Highlights all bubbles in that temporal band. Dims the other 3 bands (opacity 0.15).
Classification Cage · Respite · Simulacra · Neutral Highlights all bubbles of that classification across all bands. Cross-band comparison.
Category Emotional · Epidemiological · Political · Behaviour · Meta-digital · Philosophical Highlights by data category. Useful for seeing emotional terms across all phases.
Component style Pill-shaped chips. Height: 26px. Font: Space Mono 9px, letter-spacing 2px, uppercase. Default: dark background, border rgba(255,255,255,0.1). Active: border + text in classification colour (cage=blue, respite=amber, simulacra=green). Hover: border brightens. Placement Fixed top strip, 36px height, transparent background with blur backdrop. Appears when user hovers top 60px of screen. Collapses when cursor leaves. Does not obstruct the visualisation at rest. Interaction GSAP animate: inactive bubbles tween opacity to 0.12 over 300ms. Active bubbles pulse ring once (scale 1.0→1.3→1.0, 400ms). Deselect: all bubbles return to default opacity. All / Reset A "RESET" chip always appears first. Clicking clears all active filters.

3.2 — Flexible Band Height (Proportional to Keyword Count)

The 4 strata bands should not be equal height. Band height is calculated proportionally to the number of keywords in each phase, ensuring the data has breathing room and visual density feels honest.

Formula bandHeight[i] = (keywordCount[i] / totalKeywords) × availableHeight Keyword counts Phase 1 (Pre-COVID): 10 terms → ~18% height
Phase 2 (Lockdown): 20 terms → ~36% height
Phase 3 (Deep Lockdown): 15 terms → ~27% height
Phase 4 (Post-COVID): 10 terms → ~18% height Minimum band height 80px. If proportional calculation yields less, clamp to 80px and redistribute remaining height among other bands. Label panel width 190px fixed. Band labels remain left-aligned regardless of band height.

3.3 — Bubble Spacing and Collision Padding

The D3 force simulation must be tuned to prevent overlapping bubbles and ensure readable label text.

Collision radius d3.forceCollide(d => d.r + 8) — 8px padding between bubble edges. Strength: 1.0 (maximum). This is the primary fix for bubble overlap. Simulation ticks Run 350 synchronous ticks before render (increased from 250 in prototype). More ticks = more settled layout with fewer overlaps. X-spread force d3.forceX with per-term deterministic offset: seed with term.charCodeAt(0) to give each bubble a stable home X position. Strength: 0.04. Prevents all bubbles clustering at band centre. Y-drift semantics cage terms: pull toward bottom 25% of band. respite terms: pull toward top 25%. neutral/medium: gentle noise-based jitter (use sin(term.length × phase) for stable random-looking spread). Strength: 0.38. Post-simulation clamping After ticks, hard-clamp all bubble positions: x within [marginLeft + r + 10, W - marginRight - r - 10], y within [bandTop + r + 10, bandTop + bandH - r - 10]. No bubble should touch the band edge. Label visibility threshold Show keyword label only when bubble radius ≥ 20px. Show truncated (max 12 chars) when radius 20–28px. Show full label when radius > 28px.

3.4 — Viz Mode Toggle (3 Options)

The strata view is the primary and default visualisation. Two additional modes are available via a toggle in the top-right. Mode selection persists during the session.

Mode Description Priority
Strata View Geological 4-band layout with floating bubbles. GIF plays inside each bubble on hover. Default view. Full spec in this PRD. Primary — build first
City Stack Vertical buildings per keyword, height = codification score, GIFs stacked inside. 4 neighbourhood columns by phase. Horizontal scroll. Evolves the gif-city lineage. Secondary — v2.1
Heatmap Grid 55 cells in a treemap layout. Cell area = codification score. Colour tint = classification. GIF plays inside each cell. Dense, comparative, data-forward. Secondary — v2.1
Toggle component 3 icon buttons, top-right of visualisation. Active mode: full opacity. Inactive: 30% opacity. Hover: 60%. Tooltip on hover shows mode name. No label text needed — icons are sufficient (grid, building skyline, scatter). Mode transition Cross-fade: current view fades to 0 opacity (300ms), new view fades in (300ms). Use GSAP timeline. Positions re-calculate on mount — not animated between modes.

3.5 — GIF Rendering Inside Bubbles

Each bubble contains the top Giphy result for that keyword. GIF thumbnails render on hover (not by default — performance constraint). On hover, the bubble expands slightly and the GIF begins looping.

Data source Giphy Search API: /v1/gifs/search?q={term}&limit=1&lang=en&api_key={key} — fetch once on initialisation, cache results in a Map keyed by term string. Render method SVG <foreignObject> containing an <img> element pointing to gif.images.fixed_width_small.url. Clip-path to bubble circle. Hidden by default (opacity: 0, display: none). On hover: display block, fade in 200ms. Fallback If API call fails or returns no results: retain animated scanline pattern from prototype as the in-bubble visual. Never show broken image icon. Performance constraint Do not autoplay all 55 GIFs simultaneously. Load only the hovered GIF. Pre-fetch the 10 highest-score terms on idle (requestIdleCallback) for perceived speed.

06 — Open Questions

Top 3 Questions Before Build

01

Is the strata view the only primary viz, or do all 3 modes ship in v2?

The PRD designates strata as primary and city/heatmap as v2.1. But if Claude Code is already building the main frame, it may be more efficient to scaffold all 3 toggle states now (even if city/heatmap are placeholder skeletons) than to retrofit the toggle later. This affects component architecture from day one.

02

What's the performance ceiling for simultaneous GIF thumbnails?

The strata view has 55 bubbles. Loading all 55 GIFs on mount is likely to cause jank or API rate-limit issues. The spec recommends hover-only loading with idle pre-fetch of top 10. But does this match your expectations for the experience? If you want all GIFs visible (not just on hover), we need a different strategy — possibly a lower-res thumbnail grid or a WebP sprite sheet from the Giphy API.

03

Does the GSAP SplitText plugin exist on the current build?

The Redaction word animations in this PRD rely on character-level splitting. If GSAP SplitText isn't already included, either the plugin needs to be licensed (GSAP Club) or we implement a manual JS fallback (slightly less robust, but workable). Worth confirming before the narrative screen build starts, since it affects the animation code pattern for all 4 Baudrillard screens and the closing screen.
